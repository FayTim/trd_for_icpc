# TRD for ICPC

Командный справочник алгоритмов и структур данных на C++20.
Главный файл [`trd.typ`](trd.typ) задаёт порядок разделов и подключает
описания из отдельных папок. Документ собирается напрямую Typst;
листинги читаются из тех же файлов, которые компилируются в CI.

## Структура

```text
trd.typ                        # главный документ и подключения разделов
templates/                     # обычное и интерактивное решение, режим --test
algorithms/
  binary_search/               # граница монотонного предиката, поиск по ответу
  gray_code/                   # двоичный код Грея и изменившийся бит
  combinatorics/               # точные и модульные биномиальные коэффициенты
  fixed_set/
    description.typ            # описание, интерфейс и включение листингов
    fixed_set.h                # самостоятельная реализация
    example.cpp                # компилируемый пример использования
    test.cpp                   # тесты реализации
    CMakeLists.txt              # цели сборки и регистрация теста в CTest
  compress_coordinates/
    description.typ            # сжатие координат: описание и листинги
    compress_coordinates.h     # самостоятельная реализация
    example.cpp                # компилируемый пример использования
    test.cpp                   # тесты прямого и обратного отображения
    CMakeLists.txt              # цели сборки и регистрация теста в CTest
  scc/                         # компоненты сильной связности (Косарайю)
  two_sat/                     # 2-SAT на основе SCC
  number_theory/               # простые, делители, phi/mu, НОД и CRT
  geometry/                    # целочисленная 2D-геометрия
CMakeLists.txt                 # подключение модулей с тестами
.github/workflows/ci.yml        # тесты и PDF для PR и main
```

## Тесты

Нужны CMake 3.20 или новее, Python 3 для локального интерактора и компилятор
с поддержкой C++20, например GCC 12+ или Clang 15+.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

## Шаблоны решения

[`templates/ordinary.cpp`](templates/ordinary.cpp) отделяет `Solve(in, out)`
от запуска и встроенных тестов. [`templates/interactive.cpp`](templates/interactive.cpp)
отделяет стратегию от обмена с судьёй; в `--test` вместо реального судьи
используется локальная модель. Каждый файл можно скопировать как самостоятельное
решение на C++20 и заменить демонстрационную задачу на свою.

```sh
./build/templates/contest_template --test
./build/templates/interactive_template --test
./build/templates/contest_template < input.txt
```

Без аргументов шаблоны работают в режиме отправки на проверку. Тесты
запускаются только с `--test`, а диагностика идёт в `stderr`.
Интерактивный демопротокол нужно заменить на протокол конкретной задачи.
CTest также запускает отдельного судью через каналы процесса: он проверяет
своевременный `flush`, лимит запросов и завершение при ошибке или конце ввода.

## Проверяемые разделы

Вместе с тестами компилируются примеры `fixed_set_example`,
`compress_coordinates_example`, `scc_example`
и `two_sat_example`. Модули [SCC](algorithms/scc/README.md) и
[2-SAT](algorithms/two_sat/README.md) содержат описание интерфейса и применения.
Раздел [теории чисел](algorithms/number_theory/README.md) включает пять
самостоятельных заголовков, пять тестов и компилируемые примеры.
Для его 64-битной арифметики нужен GCC/Clang с `__uint128_t` и `__int128_t`.

Раздел графов включает [эйлеров путь и цикл](algorithms/graphs/euler.h)
для ориентированных и неориентированных мультиграфов: выбор старта,
проверка существования, восстановление вершин и id рёбер. Пример
`euler_example` компилируется, тест `euler` сравнивает результат с перебором.

Раздел [геометрии](algorithms/geometry/README.md) содержит точки и векторы,
прямые и отрезки, осевые прямоугольники, многоугольники и выпуклую оболочку.
Его четыре примера также компилируются, а тесты запускаются через CTest.

## Сборка документа

Установите [Typst CLI](https://github.com/typst/typst#installation) 0.15.0
или новее; CI использует 0.15.1. Дополнительные пакеты и системные шрифты
не нужны: документ использует шрифты из поставки Typst.

```sh
mkdir -p build/document
typst compile --root . trd.typ build/document/trd.pdf
```

Для автоматической пересборки при редактировании:

```sh
typst watch --root . trd.typ build/document/trd.pdf
```

## Печатная версия

Документ рассчитан на альбомный A4 с двумя колонками: текст 10 pt, код 8 pt,
поля 12 мм. Каждый крупный раздел начинается с новой страницы. В верхнем
колонтитуле стоят номер и короткая метка блока: `1 ШАБ`, `2 СТ`, `3 ГР`,
`4 ДП`, `5 СТР`, `6 ПРИ`, `7 ЧИС`, `8 КОМБ`, `9 ГЕО`. Боковой маркер занимает постоянную
высоту для каждого блока, поэтому цветная печать не нужна. Нижняя метка
`ГР-3/18` означает третью из 18 страниц блока; сквозной номер справа
используется в оглавлении. Числа страниц пересчитываются автоматически.

Печатайте в масштабе 100%, одну страницу PDF на сторону листа. Для
независимых тематических пачек при двусторонней печати каждый блок должен
начинаться с лицевой стороны нового листа: печатайте разделы отдельными
заданиями либо добавьте пустой оборот после блока нечётной длины.
Для альбомных листов с обычным перелистыванием слева направо выбирайте
переворот по короткой стороне. Перед всей пачкой проверьте один лист с
двумя сторонами на своём принтере.

## Добавление алгоритма

1. Создайте `algorithms/<name>/` с реализацией, `description.typ`, примером
   и тестами. За образец можно взять [`fixed_set`](algorithms/fixed_set).
2. Добавьте `CMakeLists.txt` с исполняемой целью теста и `add_test`.
   Проверки должны работать и в Release: не полагайтесь на `assert`.
3. Подключите каталог через `add_subdirectory(algorithms/<name>)` в корневом
   `CMakeLists.txt`.
4. В нужный раздел `trd.typ` добавьте `#include "algorithms/<name>/description.typ"`.
   Описание модуля начинается с `==`, его подразделы — с `===`.
5. В описании подключайте код через `#raw(read("implementation.h"), lang: "cpp", block: true)`.
   Пути отсчитываются от файла описания; копировать исходник в документ не нужно.
6. Запустите тесты и сборку PDF командами выше.

## CI

GitHub Actions запускает тесты и сборку PDF на каждом pull request и каждом
push в `main`, включая слияния PR. Задания независимы: PDF можно скачать из
артефакта `trd-pdf` у соответствующего запуска Actions. Для обязательного
прохождения проверок перед слиянием владелец репозитория может включить
required checks `Tests` и `PDF` в правилах ветки `main`.
