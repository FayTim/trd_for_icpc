# Алгоритм Мо

Подробный русский раздел включён в общий PDF через `description.typ`.
Код рассчитан на C++20, индексы с нуля, отрезки полуоткрытые `[l,r)`.
Все запросы должны быть известны заранее.

| Файл | Назначение |
| --- | --- |
| `mo.h` | `Solve`: змейка / Гильберт; `SolveWithUpdates`: третья координата времени |
| `rollback_mo.h` | `SolveRollback`, готовая частота моды `RollbackModeFrequency` |
| `tree_mo.h` | `TreeMo`: вершины / рёбра пути, итеративный обход + LCA |
| `range_statistics.h` | Различные значения, равные пары, квадраты частот, k-й через блоки / Фенвик, инверсии |
| `approximate_lis.h` | Приближённый LIS на отрезках через офлайн divide and conquer |
| `example.cpp` | Готовые функции для статического массива |
| `variants_example.cpp` | Изменения массива, пути дерева и откаты |

## Контракт состояния

`Solve(n, queries, state, order, block_size)` вызывает
`AddLeft(i)`, `AddRight(i)`, `RemoveLeft(i)`, `RemoveRight(i)` и
`Answer(id)`. Структура начинает с пустого окна. Результаты возвращаются
во входном порядке. Тип ответа должен создаваться по умолчанию и
копироваться; `Answer` не возвращает ссылку и не меняет логическое состояние.
После запуска состояние соответствует последнему обработанному окну.

`SolveWithUpdates` дополнительно вызывает `Apply(update_id, forward, l, r)`.
Структура начинает в версии массива до всех изменений; изменение внутри
окна должно обновить и текущий массив, и статистику. Для повторных изменений
позиции сохранённое `before` относится к моменту этого изменения.

`SolveRollback` требует `Snapshot()` и `Rollback(mark)` вместо удалений,
но **оба добавления всё ещё должны быть быстрыми**. В конце восстанавливает
исходное состояние. `TreeMo` вызывает `AddVertex(v)` / `RemoveVertex(v)`:
поддерживаемая статистика зависит от мультимножества, не от порядка вдоль пути.
После ответа временный LCA убирается; перед следующим запуском состояние
нужно создать заново. В режиме рёбер вершина хранит ребро от своего родителя.

Входные границы, времена, дерево и параметры должны удовлетворять контрактам
в заголовках. `block_size=0` означает автоматический размер; положительное
значение задаёт его вручную. `k` в `KthQuery` начинается с единицы и должно
лежать в `1..r-l`. Частоты никогда не должны становиться отрицательными.

## Что выбирать

- Начните со змейки и блока `n/sqrt(q)`, измеряйте число движений / время.
- Гильберт меняет порядок, но не возможности пользовательской структуры.
- Для k-го элемента сравните O(1) обновления блоков с O(log σ) у Фенвика:
  обновлений окна обычно гораздо больше, чем ответов на запросы.
- Мо с откатами помогает, когда удаление труднее добавления. Он не превращает
  append-only LIS в структуру с дешёвым добавлением слева.
- `ApproximateRangeLis` использует точные LIS двух частей, ограничивающие
  ответ, и даёт приближение с коэффициентом 1.5. Это отдельный офлайн алгоритм.

В PDF также разобраны мода, частоты частот, MEX, подотрезки с заданным XOR,
оценки сложности и более медленная блочная схема для приближённого LIS.

## Проверка

Из корня репозитория:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure -R '^mo'
./build/algorithms/mo/mo_example
./build/algorithms/mo/mo_variants_example
```

Тесты не зависят от `assert`: выполняются и в Release. Используются
направленные состояния, сравнение с перебором на случайных массивах / деревьях,
все перестановки до длины 7, массивы с повторами и крайними `int`,
64-битные ответы, цепочка дерева из 200000 вершин, движение времени в обе стороны.
